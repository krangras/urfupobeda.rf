# урфупобеда.рф

Статическое учебное приложение для подготовки: билеты АГиТДУ и теории вероятностей, задачи, физика НТК, интегралы, интервальные повторения, локальный прогресс и синхронизация через Firebase.

## Теория вероятностей

Раздел доступен через верхнюю вкладку и меню курсов и содержит только предоставленный пользователем список из 18 билетов. Для билетов 1, 2 и 3 добавлен исходный текст без изменения формулировок, доступно копирование с формулами. Теория остальных билетов готовится. Предварительная дата экзамена — 9 января 2027 года; количество билетов может измениться.

Материалы лежат в `src/data/probability_data.js` и загружаются при открытии курса. Интерфейс — `src/app/probability.js`, стили — `assets/css/probability.css`. Прогресс хранится отдельно в `probability_progress_v1`, входит в общий экспорт/импорт и синхронизацию Firebase. После замены списка прогресс первого билета сохраняется, а отметки прежних тренировочных билетов сохраняются отдельно в `legacyTickets`, чтобы не применить их к другим темам. Как в АГиТДУ, используются пять шагов с интервалами 1, 3, 7, 14 и 30 дней; после освоения билет повторяется каждые 30 дней.

Практика привязана к билетам: к билету 1 добавлены 10 предоставленных задач, у остальных билетов задач пока нет. Интерфейс в `src/app/probability-practice.js` использует карточки и проверку ответов, как в практике АГиТДУ, без решений и подсказок. В первой задаче проверяется только ответ «да/нет», обоснование сохраняется для самопроверки. Черновики ответов и отметки хранятся в `probability_practice_v1`, отдельно от повторений теории, и входят в резервные копии и синхронизацию аккаунта.

Проверка текста первого билета, интервальных повторений и обработки импортируемого прогресса (Node.js, без установки зависимостей):

```bash
node tools/test_probability.cjs
```

## Что изменено в этой версии

Проект организован следующим образом:

- стили вынесены в `assets/css/`;
- изображения и логотип вынесены в `assets/img/`;
- основной код приложения вынесен в `src/app/`;
- Firebase-код вынесен в `src/auth/`;
- большие файлы с учебными данными вынесены в `src/data/`;
- справочные материалы и технические заметки вынесены в `docs/`;
- из релизной папки убраны `__pycache__` и вложенный архив проекта.

## Локальный запуск

### Через Python

```bash
python server.py
```

После запуска открыть:

```text
http://localhost:8000
```

### Через Docker Compose

```bash
docker compose up --build
```

По умолчанию приложение будет доступно на порту `10101`, если не менять `docker-compose.yml`.

## Прогресс и резервные копии

`src/app/storage.js` обрабатывает повреждённые сохранения, числовые ответы и интервалы повторений. `src/app/backups.js` проверяет импорт целиком перед записью и экспортирует прогресс всех курсов, включая ответы практики и ещё не открытые разделы.

Гостевой прогресс и прогресс каждого Firebase UID хранятся отдельно. При входе они не объединяются автоматически; перенос гостевого сохранения доступен в профиле с подтверждением замены. Синхронизация сравнивает версии каждого ключа, включая удаления, а облачная запись выполняется в транзакции.

Рисунок к задаче 18 раздела «Электростатика» восстановлен в SVG по условию и имеющемуся решению; исходное изображение отсутствовало.

## Проверки

Нужны Node.js 22+ и Python 3. Для браузерной проверки нужен Chrome; путь можно задать переменной `CHROME_PATH` (по умолчанию используется стандартный путь Windows).

```bash
node tools/test_probability.cjs
node tools/test_core.cjs
node tools/test_probability_practice.cjs
node tools/test_sync.cjs
python tools/test_utilities.py
node tools/test_browser.cjs
```

Для проверки производительности: `node tools/benchmark_browser.cjs`. Скрипт запускает отдельный Chrome с замедлением CPU в 4 раза и сохраняет измерения в `tools/output/performance.json`: ввод 60 символов, повторное открытие физики, число отрисовок первого семестра и отсутствие лишней работы в покое. Проверяются сохранность черновика, повторное использование готовых карточек и загрузка только выбранного раздела физики.

Формулы обрабатываются последовательно небольшими порциями; скрытые разделы пропускаются. Физика загружается при открытии курса, готовые карточки сохраняются до изменения ответов или прогресса. Ввод черновика не перерисовывает счётчики, пока не меняется отметка решения.

Браузерная проверка запускает отдельный временный профиль и локальный сервер на свободном порту. Вход в настоящий Firebase-аккаунт не выполняется; сценарии смены аккаунтов и конфликтов синхронизации проверяются на изолированной модели Firestore. Для проверки отрисовки формул в браузере нужен доступ к CDN KaTeX.
